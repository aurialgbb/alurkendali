# Web modes

## Landing page

A calm B2B editorial layout with a clear reading sequence: familiar problem, concrete improvement, relevant use cases, how work proceeds, and a useful contact action. Adapt sections to the actual product; do not force the original site's outline.

Use a roomy headline plus an explanatory process illustration, a maximum content width near 1240px, and consistent alignment between sections. Alternate white, warm-neutral, and pale-blue surfaces at meaningful changes in the story. Avoid coloring every block differently.

Body copy at 16px, headings approximately 32–46px and hero 64–70px on wide screens are starting points. Scale down with the viewport. Use readable line lengths and one main action per decision point. Keep mobile controls comfortably tappable and avoid horizontal page overflow.

Scroll reveal is a one-time opacity/short-translation effect, about 0.6s and 12–16px. Default content must remain visible without JavaScript. Respect reduced motion. Keyboard focus must never land in invisible content. Looping process diagrams need pause/resume and should stop when offscreen. Avoid animating every word or delaying access to information.

Illustrations should have category-specific composition inside a consistent frame. Sample controls should not look interactive unless they work. Use static labels for illustrative states.

## Internal Finance SaaS

Keep the font, palette, alignment, moderate corners, and deliberate hierarchy; increase information density. Suggested starting sizes: page title 24–30px, section title 16–20px, tables/controls 13–14px. Use a stable sidebar or top navigation, contextual page actions, filters near the records they affect, and a clear detail view.

Amounts use tabular figures, right alignment, explicit currency and consistent precision. Distinguish zero, missing data, negative values, pending transactions, and confirmed balances. Put totals and date ranges in context. Include evidence and audit history where the task requires them. Preserve existing business logic, permissions, and accounting semantics while restyling.

Prioritize the daily workflow: review, filter, inspect evidence, approve, reconcile, export. Do not fill a working dashboard with marketing slogans or oversized empty KPI cards. Use color sparingly for exceptions, selected items and status, with text equivalents. Data tables may have their own horizontal scroll region where required; the whole page should not overflow.

Verify representative states: normal data, empty results, long labels, errors, disabled actions, keyboard focus, narrow viewport, and enlarged text. Test the actual user flow rather than testing every style token in isolation.
